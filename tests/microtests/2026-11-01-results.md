# Micro-test results, 2026-11-01

Method notes:
- Rule A and rule B use the same task, so ten single-shot subagents were run
  (five control, five skill) and each output was scored for both rules,
  instead of twenty. All were `general-purpose` agents on model sonnet.
- Control validity problem. The first five control runs auto-loaded the
  one-page-design skill (the symlink in ~/.claude/skills makes it available
  to every subagent). Fingerprints in all five: class="poster", --w/--h on
  :root, the scaffold's .t1 class, @page size from the variables; control 1
  also names one-page-design in a comment. They are kept as
  `output/ruleA-control-contaminated-N.html` and are NOT scored as controls.
- A second control set added "Do not invoke any skills" and showed no
  fingerprints. It was then overwritten by the final set below, run with
  the skill uninstalled: the symlink was moved to
  `~/.claude/skills/.one-page-design.off` for the five runs and restored
  afterwards (`ls -la` shows `one-page-design -> ../../.agents/skills/one-page-design`).
  The final controls carry the extra line "Do not load or follow any skill."
  and have zero fingerprints (no poster, no --w, no .t1, no mention of
  one-page-design or fit-check).
- The agents' three-sentence replies were never delivered (each ended
  without a handback), so no reply text is available. Scoring is from the
  HTML, read in full and rendered with headless Chrome.

## Verdict
Rule A held. With the skill all five centres are drawn rosters across the
nine choices (5/5, one shape); without it all five are headed prose with
tables and at most a small subordinate strip (0/5). No skill run failed, so
there is no rationalization to quote.

Rule B was not stressed. The control arm also produced no tabs, details or
links under "be thorough" (5/5 clean), because these single-page documents
fit on one scrolling page without needing them. The test passes for the
skill but does not discriminate: it shows no bending to prevent. A
stronger pressure test for rule B needs a task whose content genuinely
overflows one sheet (for example a mechanic with many pieces to list).

Two things for the controller:
- Skill auto-triggering contaminated the first control set. Any later
  baseline run in this session needs the "do not invoke any skills" line
  or the skill hidden.
- Several skill outputs are wider than a 1800 px viewport at 1 in = 96 px,
  which is expected for 17 to 20 in surfaces; the right edge cropped in
  my screenshots is not a fit failure.
